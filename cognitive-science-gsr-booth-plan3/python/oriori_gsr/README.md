# oriori_gsr
## 오늘 안에, 첫 번째 영수증까지

프로젝트 이름은 **oriori_gsr**입니다. 이 폴더는 뼈대가 아니라 로컬 운영 화면, 태블릿 검사, GSR 기록, 설명 생성, 영수증 출력, CSV/JSON 내보내기를 포함하는 실행 패키지입니다.

**첫 성공의 기준은 ‘장비 없이 데모 1회 완료 → 결과 표시 → PDF 저장 → CSV 확인’입니다. 장비는 그 다음에 연결하세요.**

> 중요한 구분: `pico/main.py`만 Pico에 올립니다. `app.py`는 노트북에서 실행합니다. Flask나 LLM을 Pico에서 실행하지 않습니다.

---

## 0. 지금 바로 할 일 — 딱 5개

1. ZIP을 **압축 해제**해서 바탕화면에 `oriori_gsr` 폴더를 만듭니다. ZIP 내부에서 바로 실행하지 마세요.
2. [Python 공식 설치 페이지](https://www.python.org/downloads/)에서 **Python 3.11 이상**을 설치합니다. Windows는 **Add Python to PATH**를 체크합니다.
3. Windows: `start_windows.bat` 더블클릭. macOS: 폴더에서 터미널을 열고 `bash start_mac.sh`를 실행합니다.
4. 처음에는 인터넷으로 라이브러리를 자동 설치합니다. 검은 창을 닫지 마세요. 브라우저가 열리지 않으면 `http://127.0.0.1:8765`를 직접 엽니다.
5. **새 검사 시작 → FULL → 세션 만들기 → 이 기기에서 검사 열기 → 참여 동의 → 10문항 → 측정 시작 → 결과 → 영수증 인쇄/PDF 저장**.

첫 설정은 센서 없는 `demo` 모드입니다. API 키도 프린터도 필요 없습니다. FULL 센서 데모는 40초, BASIC 16초, RELATION 26초입니다. 데모는 실제 데이터가 아니며 반드시 분석에서 제외하세요.

첫 설치 후에는 **로컬 UI·폰트·규칙 기반 설명·수집·인쇄를 인터넷 없이 사용**할 수 있습니다. LLM 설명만 인터넷과 선택 동의가 필요합니다. 태블릿은 같은 로컬 네트워크에 있어야 합니다.

### 안 열릴 때

- Python 설치 직후라면 창을 닫고 다시 실행합니다.
- 실행 창 마지막 오류를 읽습니다. 오류를 숨기지 않도록 구성했습니다.
- `Address already in use`: 이전 실행 창을 종료하거나 `config.json`의 `port`를 8766으로 바꿉니다.
- 설치 중 실패: 인터넷을 확인하고 같은 실행 파일을 다시 실행합니다. 다운로드가 모두 끝나기 전에 창을 닫지 마세요.
- macOS `python3`가 너무 오래됐다면 python.org에서 새 버전을 설치합니다.
- ‘인식할 수 없는 앱’ 경고를 무조건 우회하지 마세요. 이 문서와 소스 코드를 확인하고 본인이 받은 폴더인지 확인하세요.

## 3. 배선 — 안전부터

**정확한 GSR 모듈 모델이 확인되지 않았으므로 공급 전압·출력 범위·저항→전도도 교정식을 추측하지 않습니다.** 모듈 데이터시트를 먼저 확인하세요. 확인할 수 없으면 하드웨어를 연결하지 말고 데모를 사용하세요.

Pico ADC/GPIO는 **0~3.3V 입력**입니다. 5V 신호를 직접 연결하지 마세요. 5V 전원 모듈의 출력이 3.3V를 넘는다면 적절히 설계·검증된 레벨 변환/분압·보호가 필요합니다. 전원 5V와 신호 5V는 다른 문제입니다. VCC 전압은 각 모듈 사양을 따라야 합니다.

| 모듈 | 신호 | Pico GPIO | 물리 핀 | 참고 |
|---|---|---|---|---|
| GSR | 아날로그 출력 | GP26 / ADC0 | 31 | 입력 0~3.3V만 |
| DHT11 | DATA | GP15 | 20 | 필요하면 3.3V DATA 풀업. 2초 간격 읽기 |
| KS0029 버튼 | S | GP14 | 19 | 기본 active-low. 모듈 사양·실측 확인 |
| 사운드 모듈 | AO | GP27 / ADC1 | 32 | **AO가 있는 경우만**, 비보정 상대값 |
| 공통 접지 | GND | GND | 예: 38 | 반드시 공통 접지 |
| 3.3V 호환 모듈만 | VCC | 3V3 OUT | 36 | 3.3V 동작이 확인된 모듈에 한함 |

SZH-EK03이 DO만 제공하거나 전압 범위를 알 수 없다면 `USE_SOUND=False`로 두세요. DO를 ADC 음량처럼 사용하지 않습니다. 원시 사운드 ADC는 dB도, 목소리 크기의 검증된 지표도 아닙니다. 마이크 음성·피치 분석과 초음파 센서는 이 배포의 측정 항목이 아닙니다. 원본 음성은 수집하지 않습니다.

- 전원을 뺀 상태로 연결합니다. USB·전원 배선과 신호선을 혼동하지 마세요.
- 사람 피부에 연결하는 비의료 실험 장치입니다. 승인된 교육용 장비와 안전한 저전압 전원을 사용하고, 배터리 전원 노트북을 권장합니다. 상처난 피부, 통증, 따가움이 있으면 즉시 중단합니다.
- 전극은 제조사 지침에 따라 세척·소독하고 완전히 건조합니다. 피부를 젖게 해서 반응을 억지로 만들지 마세요.
- 절대 보정 전 `ADC → μS`로 변환하지 않습니다. 이 코드는 원시 ADC와 기준선 대비 상대 변화만 계산합니다.

## 4. Thonny → Pico → 실제 수집

1. Pico BOOTSEL을 누른 채 USB 연결합니다.
2. [공식 MicroPython Pico 펌웨어](https://micropython.org/download/RPI_PICO/)를 설치합니다. Pico W/2는 해당 모델 펌웨어를 사용하세요.
3. [Thonny](https://thonny.org/)에서 인터프리터를 MicroPython (Raspberry Pi Pico)로 선택합니다.
4. 이 패키지의 `pico/main.py`를 열고 **Pico 장치의 `main.py`**로 저장합니다.
5. 다시 실행/재연결해 셸에 `seq, t, adc, temperature, humidity, sound, button`을 가진 JSON이 흐르는지 확인합니다.
6. **Thonny를 완전히 종료**하고 Pico를 다시 연결합니다. 한 포트를 Thonny와 앱이 동시에 열 수 없습니다.
7. `config.json`에서 `mode`를 `hardware`, `serialPort`를 실제 포트로 수정합니다. Windows 예 `COM3`, macOS 예 `/dev/tty.usbmodem1101`. 포트 번호는 추측하지 마세요.
8. 학교 승인·필요한 보호자 동의를 확인한 후에만 `schoolApprovalConfirmed`를 `true`로 바꿉니다. 이 체크는 연구 윤리 승인을 대신하지 않습니다.
9. 앱을 재실행합니다. 운영 화면 ‘실시간 센서’에서 움직이는 실제 ADC를 확인합니다. Pico를 뽑으면 연결 상태가 끊기는지도 확인하세요.
10. 포트 목록은 운영 노트북에서 `http://127.0.0.1:8765/api/ports`로 확인할 수 있습니다.

DHT11 통신과 USB 출력 때문에 정확히 20Hz가 아닐 수 있습니다. 실측 타임스탬프, 샘플 시퀀스, 결측 수, 관측 주파수를 남깁니다. 폴링/디바운스 지연이 있는 교육용 장비입니다.

## 5. 노트북은 운영, 태블릿은 참가자

1. 노트북의 개인 핫스팟을 켜고 태블릿을 연결합니다. 학교 Wi-Fi는 기기간 통신을 막을 수 있습니다.
2. 앱 터미널에 표시된 `Tablet: http://192.168…:8765/tablet` 주소를 사용합니다. 태블릿에서 `localhost`는 태블릿 자신이므로 사용하지 않습니다.
3. 노트북 운영 화면에서 **새 검사 시작 → 코스 선택 → 세션 만들기**.
4. 발급된 세션 QR을 태블릿에서 스캔합니다. QR에는 추측하기 어려운 세션 토큰이 들어갑니다. 이 링크를 다른 사람에게 공유하지 마세요.
5. 태블릿에서 동의·설문·측정을 진행합니다. 노트북의 세션 표는 자동 갱신됩니다.
6. 완료 후 태블릿에는 결과만, 노트북에는 저장/출력/삭제 기능이 제공됩니다.

운영 API는 localhost에서만 허용됩니다. 태블릿에서 운영 메뉴를 열면 차단되는 것이 정상입니다. 결과 링크는 토큰을 아는 사람에게 공개되므로 민감한 링크로 취급하세요. 앱은 인증된 인터넷 서비스가 아닙니다. **공유기 포트포워딩·공개 터널 금지, 신뢰할 수 있는 개인 핫스팟에서만 사용**하세요.

연결 실패: 주소의 IP/포트 확인 → 같은 핫스팟인지 확인 → VPN 해제 검토 → 방화벽에서 개인 네트워크의 Python만 허용 → 보안 정책 확인. 방화벽 전체를 끄지 마세요. 자동 IP가 다른 어댑터를 선택했다면 `ipconfig`/네트워크 설정에서 실제 핫스팟 IP를 찾아 동일 세션 경로로 접속합니다.

## 6. Xprinter — 브라우저 먼저, 자동 커터는 다음

### 가장 쉬운 성공 경로
1. 정확한 모델의 제조사 드라이버 설치.
2. OS에서 프린터 테스트 페이지 성공 확인.
3. 운영 화면 → 완료된 결과 → 영수증/인쇄 화면 → **브라우저 인쇄**.
4. 프린터 또는 PDF 선택. 헤더·푸터 끄기, 여백 최소, 실제 감열지 너비 선택.

### ESC/POS 직접 인쇄 + 자동 커터
실제 프린터가 ESC/POS 래스터 이미지와 커터를 지원하는지 모델 문서에서 확인해야 합니다. 모든 ‘Xprinter’가 같은 VID/PID/명령어를 쓰지는 않습니다.

`config.json`의 `printer`:
- `browser`: 기본. 브라우저/PDF, 커터 명령은 보내지 않음.
- `win32`: Windows 제조사 드라이버가 RAW ESC/POS를 전달하는 경우. `printerName`에 Windows 프린터 이름을 정확히 입력.
- `usb`: 네이티브 USB ESC/POS. `printerVid`, `printerPid`, `printerInEndpoint`, `printerOutEndpoint`를 실제 장치 값으로 입력. VID/PID는 `0x...` 문자열.
- `network`: `printerHost`에 프린터의 실제 LAN IP. 기본 포트 9100.

`paperWidth`: `58`은 384px, `80`은 576px로 렌더링합니다. 모델의 인쇄 가능 도트 폭이 다르면 `engine.py`의 폭을 조정해야 합니다. 기본 한글 폰트를 이미지로 출력하므로 코드페이지 깨짐을 줄입니다. `autoCut: true`는 이미지 출력 후 커터 명령을 보냅니다. 커터 미지원이면 false로 바꾸세요.

USB libusb 드라이버 교체는 기존 Windows 인쇄를 망가뜨릴 수 있습니다. **Zadig를 무조건 실행하지 마세요.** 먼저 Win32/제조사 경로를 시험하고, USB 직접 제어가 꼭 필요할 때 정확한 프린터 장치와 드라이버 복구 방법을 확인하세요. 다른 USB 장치 드라이버를 바꾸지 마세요.

실패하면 오류를 표시합니다. 출력 성공으로 위장하지 않습니다. 브라우저 인쇄 버튼으로 대체하세요. BASIC의 물리 출력은 기본 비활성화이며 PDF/화면 결과를 사용합니다. 종이 출력의 성공 여부와 결제 여부는 운영자가 직접 확인해야 합니다.

## 7. LLM은 선택. 계산은 코드.

기본값은 **규칙 기반 설명**입니다. 인터넷/API가 없어도 전부 진행됩니다.

원하면 `.env.example`을 `.env`로 복사하고 본인의 `OPENAI_API_KEY`를 입력합니다. 기본 모델은 `gpt-4o-mini`, `OPENAI_MODEL`로 바꿀 수 있습니다. 재실행 후 참가자가 **외부 AI 전송 선택 동의**를 한 세션에만 요약 점수를 전송합니다.

- Responses API + JSON Schema + `store: false`.
- 전달: Big5 환산 점수, 집계 센서 지표, 데모 여부.
- 전달하지 않음: 이름, 연락처, 원본 음성, 문항별 원본 응답.
- `store: false`는 제공자의 모든 로그/안전 모니터링 보관이 없다는 보장이 아닙니다. 최신 제공자 데이터 정책을 확인하세요.
- 설명에는 숫자를 새로 쓰지 못하게 하고 반환값을 검증합니다. 숫자·형식 오류·타임아웃이면 규칙 기반 문장으로 대체합니다.
- AI 문장은 오류가 있을 수 있으므로 운영자가 확인하고 인쇄하세요. 진단·고정 성격·감정 판독을 주장하지 마세요.
- `.env`와 원시 데이터는 절대 GitHub에 업로드하지 마세요.

## 8. 데이터는 어디 있나요?

`data/<랜덤 UUID>/` 아래에 저장됩니다.
- `session.json`: 코스, 동의, 응답, 점수, 분석, 설명, 버전, 모드.
- `raw.csv`: ADC·환경·버튼·시퀀스·기기/호스트 시계. **수집 즉시 추가 저장**.
- `events.csv`: 자극·응답·시작·종료·중단·가시성 등의 이벤트.
- `receipt.png`: 직접 프린터 출력 시 렌더링한 이미지.

운영 메뉴 **데이터 보관함**에서 CSV 및 전체 JSON을 내려받습니다. 삭제하려면 세션을 클릭해 **세션과 원시 데이터 삭제**. 연결된 파일이 함께 영구 삭제됩니다. 앱 종료/장애 후 재시작하면 미완료 측정을 ‘중단’으로 바꾸고 부분 raw를 보존합니다. 원시 파일은 프로세스 오류에 견디기 위해 매 행 파일을 닫지만, 전원 차단 내구성을 보장하는 의료/연구 저장 장치는 아닙니다. 주기적으로 암호화된 백업을 하세요.

로컬 앱은 시작 시 기본 30일이 지난 세션을 자동 삭제합니다. 계속 실행 중에는 새로 시작할 때까지 자동 정리가 미뤄집니다. 내보낸 사본·백업은 별도로 삭제해야 합니다. 운영 웹 미리보기는 데모 DB이므로 실제 참가자 데이터의 보관소로 사용하지 마세요.

`python analyze.py`는 라이브러리 추가 없이 하드웨어 완료 세션의 QC 요약을 `analysis_summary.csv`로 만듭니다. 데모는 기본 제외합니다. 결과는 탐색적이며 유의성·인과·성격 예측을 자동 선언하지 않습니다. 상세 변수 설명은 `DATA_DICTIONARY.md`.

## 9. 정확성, 연구 윤리, 포트폴리오

**이 배포의 10문항은 자체 제작 체험용입니다. 검증된 한국어 BFI, TIPI, 공식 MBTI가 아닙니다.** 5요인 방향을 탐색하지만 심리측정 타당성을 확보하지 않았습니다. 실제 연구에는 사용 허가·대상 연령·타당화가 확인된 척도와 채점 규칙으로 별도 프로토콜을 설계하세요. 기존 데이터와 버전을 섞지 마세요.

Big5와 MBTI 간 상관이 있다고 개인의 공식 MBTI를 정확히 변환할 수 있는 것은 아닙니다. 이 앱의 4글자 출력은 임의 50점 기준의 **참고 표현**입니다. 점수는 응답 범위 0–100 환산이지 백분위/확률이 아니며, 50 부근의 이분화는 특히 불안정합니다. 신경성 N과 MBTI 직관 N은 다른 개념입니다.

GSR은 자극에 대한 비특이적 생리 변화입니다. 감정·거짓말·사랑·미주신경 기능·폴리베이걸 상태·소마틱 마커를 판독하지 않습니다. 몸 알아차림의 버튼과 EDA 피크의 일치가 검증된 인터로셉션 정확도를 뜻하지 않습니다. 이 짧은 스피치는 표준 TSST가 아닙니다. DHT11 환경 기록은 유용하지만 정확도를 입증하거나 자동으로 교란을 제거하지 않습니다.

미성년자의 연구 활용에는 기관·법령에 따른 윤리 검토, 보호자 동의 및 본인 동의/동의능력 요건이 필요할 수 있습니다. **학교 축제 체험 동의 한 줄로 연구 동의가 완성되지 않습니다.** 연구 활용은 이 배포에서 비활성화입니다. 유상 체험 참여와 연구 기여를 묶어 강제하지 마세요. 익명 ID라도 생리/성향 자료는 민감하게 취급합니다. 원시 참가자 데이터 공개는 기본 금지입니다.

좋은 포트폴리오: 공개 가능한 소스 + 합성 예제 + 프로토콜 버전 + 타임스탬프 오차/결측/QC 분석 + 파일럿 수정 로그 + 실패와 한계 + 재현 가능한 분석. 표본 수가 특정 숫자를 넘었다고 논문/입학이 보장되지 않습니다. 축제 표본은 선택 편향·짧은 측정·센서 한계가 큽니다. 가설·분석·제외 기준은 **데이터를 보기 전에** 정하고 날짜를 남기되, 이미 본 데이터에 소급해 사전등록이라고 부르지 마세요.
